# Telnyx Wireless for IoT: SIMs, Networking, Voice, Monitoring, and Device Guides

*Part 1 of 2 — see also: [Part 2](telnyx-wireless-for-iot-sims-networking-voice-monitoring-and-device-guides--part-2.md)*

A consolidated guide to building and operating IoT fleets on Telnyx Wireless — covering SIM and eSIM provisioning, lifecycle and group policy, data networking options (public internet and Private Wireless Gateways), traffic filtering and geofencing, usage monitoring and troubleshooting, voice with mobile numbers, AT command basics, and step-by-step device setups.

## SIM types and core resources
- SIM Card: Physical or eSIM, managed as the same SIM Card resource (ICCID, status, data/voice settings, tags).
- SIM Card Group: Apply shared policy to many SIMs (data limits, network controls, PWG assignment).
- Mobile Phone Number: Assigned when you enable voice/messaging; configure forwarding, recording, screening, and routing.

## Ordering and provisioning SIMs & eSIMs
- Physical SIMs: Order in Mission Control Portal. Register each SIM using its printed registration code (portal or POST /actions/register/sim_cards). Then enable it (POST /sim_cards/{id}/actions/enable).
- eSIMs: Purchase via portal or POST /actions/purchase/esims. You receive an activation code for OTA download. After provisioning, eSIMs behave like any SIM Card resource.

## SIM lifecycle and statuses
- User-controlled: enabled (on network, passes traffic), disabled (off network, IP released), standby (off network, IP preserved). State changes are asynchronous and return actions you can poll.
- Transitional: registering, enabling, disabling, setting_standby.
- System-imposed: data_limit_exceeded (raise limit or wait for reset), unauthorized_imei (update authorized_imeis and re-enable), blocked/abolished (resolve billing). A SIM must belong to a SIM Card Group before you can enable or set standby.
- Deletion: DELETE /sim_cards/{id} is irreversible for both physical SIMs and eSIMs; prefer disable/standby for reuse.

## Groups vs bulk operations
- Groups = ongoing policy that applies to all current and future members. Configure via PATCH /sim_card_groups/{id}. Typical settings: name, data_limit. Group actions (async) include assigning/removing a Private Wireless Gateway or a wireless blocklist.
- Bulk operations = one-time async actions on an explicit list of SIM IDs. Examples: bulk enable/disable voice, bulk set public IPs, validate registration codes. Track via List Bulk SIM Card Actions; per-SIM results may vary.

## Data connectivity essentials
- APN for public internet: data00.telnyx (leave other APN fields blank on devices unless required). Enable data roaming and use LTE/4G/3G as applicable.
- APN-based IP behavior: data00.telnyx provides dynamic IP per session; data.net provides static IP across sessions (where supported).
- Multi-IMSI: Telnyx SIMs hold multiple IMSIs and auto-select the best for location/latency/rates; can be overridden per SIM or group via API. OTA updates may change IMSI profiles over time.

## OTA updates (SIM-level)
- Telnyx can push SIM applet changes like IMSI profile switches and preference updates. Updates queue and apply when the device next attaches. Use GET /ota_updates and GET /ota_updates/{id} to list and inspect, including type, status, and settings.

## Public IPs (internet-reachable SIMs)
- By default, SIMs receive private, outbound-only IPs.
- Assign a static public IP per SIM to allow inbound access (e.g., SSH, device-hosted services) and simplify firewall allowlists.
- Endpoints: GET /sim_cards/{id}/public_ip, POST /sim_cards/{id}/actions/set_public_ip, POST /sim_cards/{id}/actions/remove_public_ip, and bulk_set_public_ips.

## Private Wireless Gateways (PWG)
- Purpose: Route SIM traffic into your private network (VRF) instead of the public internet for security, control, and direct addressing of devices.
- Architecture: PWG connects to a Telnyx VRF; you bridge it to your network via Cloud VPN (WireGuard) or VXC. Interfaces in the same VRF can reach each other.
- Setup overview:
  1) Create a Network in the portal and add a VPN Interface (Cloud VPN). Store the private key; skip public IP if not needed.
  2) Create a PWG interface, choose the same region/network, wait until provisioned.
  3) Associate the PWG to a SIM Card Group; SIMs in that group route through the PWG and typically lose public internet by default.
  4) Coordinate default gateway/routing with Telnyx support if needed, including opening internet egress for your VRF when required.
- Notes: Default IP range may be limited; region availability expands over time. For static IP inside your network, use the data.net APN.

## Traffic policy profiles (network filtering & throttling)
- Define what traffic SIMs may send/receive at the network level before it reaches devices.
- Types: whitelist (only listed traffic allowed), blacklist (listed traffic blocked), throttling (bandwidth limited via limit_bw_kbps).
- Criteria: services (predefined PCEF service IDs), ip_ranges (CIDRs), domains. Create profiles via POST /traffic/policy/profiles and assign them at the group level.

## Wireless blocklists (network attachment control)
- Restrict which networks a SIM may attach to by country (ISO code), MCC, or PLMN. One blocklist per group, effective immediately for all members.
- Workflow: POST /wireless_blocklists, then set wireless_blocklist_id on the SIM Card Group.
- Common uses: geofencing, avoiding specific carriers, regional security lockdown (especially combined with PWG).

## Monitoring usage and spend
- Data limits: Set monthly caps on groups (PATCH /sim_card_groups/{id}) or per SIM override (PATCH /sim_cards/{id}). SIMs exceeding limits enter data_limit_exceeded.
- Per-SIM usage notifications: Create thresholds via the sim_card_data_usage_notifications endpoints to alert before limits are hit.
- Consumption views: Group consumed_data is returned on GET /sim_card_groups/{id}; per-SIM usage appears in SIM detail and in the portal.

## Connectivity logs and Wireless Detail Records (WDR)
- Connectivity logs: Recent registration/data sessions for a SIM via GET /sim_cards/{id}/wireless_connectivity_logs; includes registration/data states, MCC/MNC, IMSI/IMEI, radio tech.
- WDR reports: Asynchronous, time-bounded session reports with start/stop, bytes, RAT, MCC/MNC, APN, assigned IPs, and cell_id. Create (POST /wireless/detail/records/reports), poll, then download via report_url.
- Use cases: Billing reconciliation, anomaly detection, coverage analysis, troubleshooting.

## Troubleshooting connectivity
- Device configuration checklist:
  - Enable cellular data and roaming.
  - Network mode: 3G/LTE or 4G/LTE; initial registration may require at least 3G/LTE capability depending on device.
  - APN: data00.telnyx (Name: Telnyx). Update device firmware and reboot.
- Patterns and fixes:
  - No logs at all: Device not reaching Telnyx or SIM disabled. Manually scan/select a network, verify APN/roaming, and confirm SIM status/limits/billing.
  - Multiple registrations but no data: Ensure data roaming is on and APN is correct.
  - Registration succeeds but no data sessions: Recheck APN and roaming settings.
- First attach can take up to 30 minutes as the SIM builds a priority operator list (common across many device guides).

## Voice, mobile numbers, and call features
- VoLTE (beta): Add a real cellular line to eSIM-capable devices with full API control.
- Enabling voice on a SIM: Use POST /sim_cards/{id}/actions/enable_voice (optionally provide connection_id for a Mobile Voice Connection). Disable with the corresponding action. Bulk variants are available.
- Managing the Mobile Phone Number: List, retrieve, and update via mobile_phone_numbers endpoints. Key settings include call_forwarding (unconditional, no_answer with timeout, or busy), call_recording (inbound/outbound/both) with recordings accessible via Telnyx Recordings APIs, inbound_call_screening (free; evaluates number reputation, validation, SHAKEN/STIR; choose flag or reject), caller ID/CNAM settings, noise_suppression, and routing association (connection_id).
- Webhooks: Inbound call screening can populate call_screening_result in call.initiated webhooks. Configure webhook URLs on the Mobile Voice Connection.
