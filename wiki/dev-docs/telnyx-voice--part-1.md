# Telnyx Voice

*Part 1 of 2 — see also: [Part 2](telnyx-voice--part-2.md)*

Telnyx Voice is a programmable voice platform combining a REST API (Programmable Voice / Call Control), an XML-based markup language (TeXML), SIP trunking, WebRTC SDKs, and AI-powered services. It supports inbound and outbound PSTN calling, conferencing, call queuing, recording, media streaming, SIPREC recording, speech-to-text, text-to-speech, conversation relay, AI assistants, deepfake detection, noise suppression, and custom voice design. The platform includes SIP trunking with multiple authentication methods, outbound voice profiles, STIR/SHAKEN attestation, dynamic E911, and WebRTC SDKs for browser and mobile applications.

## Overview

Telnyx Voice is a programmable voice platform that combines a REST API (Programmable Voice / Call Control), an XML-based markup language (TeXML), SIP trunking, WebRTC SDKs, and AI-powered services (speech-to-text, text-to-speech, conversation relay, AI assistants). The platform supports inbound and outbound PSTN calling, conferencing, call queuing, recording, media streaming, and SIPREC recording.

## Programmable Voice API

The Programmable Voice API (formerly Call Control) provides REST endpoints for initiating and controlling calls. A Voice API Application defines how Telnyx handles calls to and from your numbers, including webhook URLs, anchor site selection, codecs, and channel limits. An [Outbound Voice Profile](outbound-voice-profiles.md) controls routing, billing, and rate limits for outbound calls and must be associated with the Voice API Application.

### Core Concepts

- **Voice API Applications** — handle inbound and outbound calls, route webhooks, configure codecs and channel limits.
- **Outbound Voice Profiles** — control outbound call routing, destinations, billing, and rate limits.
- **Webhooks** — deliver real-time call events to your server.

### Sending Commands

Voice API commands are sent with a `call_control_id` obtained from a webhook or the initial Dial response. Authentication uses the `Authorization: Bearer YOUR_API_KEY` header. Available commands include Answer, Bridge, Dial, Hangup, Reject, Transfer, Record Start/Stop/Pause/Resume, Playback Start/Stop, Speak, Gather Using Audio/Speak/AI, Send DTMF, Send SIP INFO, Refer, Enqueue, Leave Queue, Forking Start/Stop, Streaming Start/Stop, Transcription Start/Stop, SIPREC Start/Stop, AI Assistant Start/Stop, Suppression Start/Stop, Client State Update, and Conversation Relay Start.

### Receiving Webhooks

Webhooks are delivered to the primary URL on the Voice API Application, with failover to a secondary URL if delivery fails. Telnyx does not enforce webhook ordering and retries on non-2xx responses. Use a unique `command_id` on each command to deduplicate within 60 seconds. Common webhook fields include `record_type`, `event_type`, `id`, `occurred_at`, `call_control_id`, `call_leg_id`, `call_session_id`, `connection_id`, `client_state`, `from`, `to`, `direction`, and `state`.

### Command Retries

For reliability, send a unique `command_id` (UUIDv4 recommended) with each command, retry on 5XX errors, and retry on latency greater than 500ms.

### Webhook Event Types

- **Call state**: `call.initiated`, `call.answered`, `call.hold`, `call.unhold`, `call.hangup`, `call.bridged`
- **Audio playback**: `call.playback.started`, `call.playback.ended`, `call.speak.started`, `call.speak.ended`
- **DTMF and gather**: `call.dtmf.received`, `call.gather.ended`
- **Recording**: `call.recording.saved`
- **AMD**: `call.machine.detection.ended`, `call.machine.greeting.ended`, `call.machine.premium.detection.ended`, `call.machine.premium.greeting.ended`, `call.machine.premium.call_screening.detected`
- **Media forking**: `call.fork.started`, `call.fork.stopped`
- **Queue**: `call.enqueued`, `call.dequeued`
- **Transcription**: `call.transcription`
- **Streaming**: `streaming.started`, `streaming.stopped`

## Answering Machine Detection (AMD)

AMD runs real-time detection on answered calls to determine human vs. machine. Settings include `detect`, `detect_beep`, `detect_words`, `greeting_end`, `premium`, and `premium_ios_call_screening_detection`. Premium AMD uses advanced speech recognition and returns results like `human_residence`, `human_business`, `machine`, `silence`, `fax_detected`, or `not_sure`. iOS Call Screening detection handles Apple Call Screening prompts.

## Media Streaming

Media Streaming forks call media to a WebSocket URL in real time. Configure `stream_url` and `stream_track` (`inbound_track`, `outbound_track`, or `both_tracks`) on Dial or Answer. Bidirectional streaming supports RTP and MP3 modes with codecs including PCMU, PCMA, G722, OPUS, AMR-WB, and L16. WebSocket frames include `connected`, `start`, `media`, `stop`, `clear`, `mark`, `dtmf`, and `error` events.

## Conversation Relay

Conversation Relay connects a live call to a WebSocket application, with Telnyx handling speech recognition and text-to-speech. Start it from TeXML using `<Connect><ConversationRelay>` or via the `conversation_relay_start` command. Frames sent by Telnyx include `setup`, `prompt`, `dtmf`, `interrupt`, and `error`. Frames sent by your application include `text`, `play`, `sendDigits`, `language`, and `end`.

## AI Assistants and Gather Using AI

Attach a pre-configured AI assistant to an active call with `ai_assistant_start`, or use `gather_using_ai` to collect structured information via a JSON Schema. The `<AIGather>` TeXML verb and `<AIAssistant>` TeXML verb provide equivalent functionality. Use `ai_assistant_join` to add participants to an existing conversation.

## Deepfake Detection

Deepfake Detection analyzes live call audio to determine whether the remote party's voice is human or AI-generated. Enable via `deepfake_detection` on Dial or Answer. Results arrive via `call.deepfake_detection.result` webhook with `result` (`real`, `fake`, `silence_timeout`), `score` (0.0–1.0), and `consistency` (0–100).

## Noise Suppression

Enable noise suppression via `suppression_start` with `direction` (`inbound`, `outbound`, or `both`). Supported engines include `Denoiser` (default), `DeepFilterNet`, `Krisp`, and `AiCoustics`. Each direction is billed separately.

## Speech-to-Text

Telnyx STT transcribes audio via three paths: WebSocket streaming, file-based REST API, and in-call transcription. Supported engines include Google, Telnyx (Whisper), Deepgram (nova-2, nova-3, flux), Azure, xAI (Grok STT), AssemblyAI, Speechmatics, and Soniox. The REST endpoint at `POST /v2/ai/audio/transcriptions` is OpenAI SDK compatible. WebSocket endpoint: `wss://api.telnyx.com/v2/speech-to-text/transcription`.

## Text-to-Speech

TTS is available via WebSocket streaming, REST API, and in-call playback. Voice format is `Provider.Model.VoiceId`. Telnyx native voices include Natural, NaturalHD, KokoroTTS, Qwen3TTS, Ultra, Grok, Bayan, and Sukhan. Third-party providers include AWS Polly, Azure, ElevenLabs, Minimax, Resemble, Inworld, Rime, and Fish Audio. Pronunciation dictionaries support alias and IPA phoneme replacements.

## Queueing Calls

Use the `enqueue` command to place a call in a named queue. Use the `bridge` command with a `queue` parameter to dequeue and bridge. Calls leave queues via hangup, bridge/transfer/conference join/refer, `max_wait_time_secs` timeout, or the `leave_queue` command.

## Storing Call Recordings

Recordings are stored in Telnyx S3 buckets by default with a 10-minute download link in the `call.recording.saved` webhook. Custom storage is supported for GCS, S3, and Azure Blob Storage via the `custom_storage_credentials` endpoint.

## SIPREC

SIPREC (Session Initiation Protocol Recording) enables standardized call recording. Create a SIPREC connector, then start a session via `siprec_start` or the TeXML `<Siprec>` verb. Telnyx also provides a SIPREC Server (SRS) for receiving SIPREC calls.
