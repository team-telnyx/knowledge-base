# Telnyx Voice

*Part 2 of 2 — see also: [Part 1](telnyx-voice--part-1.md)*

Telnyx Voice is a programmable voice platform combining a REST API (Programmable Voice / Call Control), an XML-based markup language (TeXML), SIP trunking, WebRTC SDKs, and AI-powered services. It supports inbound and outbound PSTN calling, conferencing, call queuing, recording, media streaming, SIPREC recording, speech-to-text, text-to-speech, conversation relay, AI assistants, deepfake detection, noise suppression, and custom voice design. The platform includes SIP trunking with multiple authentication methods, outbound voice profiles, STIR/SHAKEN attestation, dynamic E911, and WebRTC SDKs for browser and mobile applications.

## TeXML

TeXML is an XML-based markup language for defining call control instructions. A TeXML Application defines how inbound and outbound calls are handled, including webhook URLs, voice method, and status callback configuration.

### TeXML Verbs

- `<Response>` — root element
- `<Say>` — text-to-speech
- `<Play>` — play audio file or DTMF tones
- `<Pause>` — silent pause
- `<Hangup>` — end the call
- `<Reject>` — reject the call
- `<Redirect>` — transfer to another TeXML document
- `<Dial>` — connect to a number, SIP endpoint, conference, or queue
- `<Enqueue>` — place call in a queue
- `<Leave>` — remove call from queue
- `<Gather>` — collect DTMF or speech input
- `<AIGather>` — collect structured data via AI
- `<Record>` — record call audio
- `<Refer>` — SIP REFER transfer
- `<Start>` / `<Stop>` — start/stop nested services (Suppression, Transcription, Stream, Recording)
- `<Connect>` — start synchronous service (Stream, ConversationRelay, AIAssistant)
- `<HttpRequest>` — send HTTP request to external server

### TeXML Compatibility

TeXML supports most TwiML verbs and nouns. TeXML-specific additions include `<AIGather>`, `<HttpRequest>`, and `<AIAssistant>`. TeXML does not support `<Pay>`, `<Client>`, `<Room>`, or `<VirtualAgent>`.

### TeXML Bin

TeXML Bin allows uploading TeXML files to storage for use without a custom server. Supports dynamic parameters via Mustache templating.

### TeXML Instruction Fetching

On inbound calls, Telnyx fetches TeXML from the URL on the TeXML Application. On outbound calls, instructions can be triggered via the TeXML Calls API or by configuring a SIP trunking connection to "Park Outbound Calls".

## SIP Trunking

Telnyx SIP trunking uses SIP Connections for inbound traffic and Outbound Voice Profiles for outbound routing.

### Authentication Methods

- **Credential-based** — username/password SIP registration
- **IP + Token** — `X-Telnyx-Token` header with IP validation
- **IP + Tech Prefix** — 4-digit prefix prepended to dial string
- **IP + P-Charge-Info** — phone number in `P-Charge-Info` header
- **FQDN** — hostname-based inbound routing

### SIP URI Calling

Enable inbound calls to SIP usernames in the format `username@sip.telnyx.com`. Access control modes: `disabled`, `unrestricted`, or `internal`.

### Caller ID Policy

Telnyx enforces strict caller ID validation. Accepted formats depend on connection localization. SIP header priority: `P-Preferred-Identity` > `P-Asserted-Identity` > `Remote-Party-Id` > `FROM`.

### Concurrent Call Limits

Default limits: 2 concurrent calls initially, 10 after Level 2 verification. Exceeding limits returns SIP 403 "User channel limit exceeded D1".

### Outbound Voice Profiles

Control routing, billing, destinations, channel limits, and call recording for outbound SIP calls. Supports rate decks, max destination rate, and daily spend limits.

### Network Configuration

- **SIP signaling**: port 5060 (UDP/TCP), 5061 (TLS)
- **RTP media**: ports 16384–32768 (UDP)
- **STUN**: `stun.telnyx.com:3478`
- **TURN**: `turn.telnyx.com:3478`
- **SRV records**: `_sip._udp.example.com` pointing to `sip.telnyx.com`

### AnchorSite

Determines which Telnyx PoP handles media routing. Modes: `latency` (automatic) or manual selection of a specific PoP.

### Failover and Retries

Telnyx uses two geographically redundant signaling IPs per region. Failover triggers on 408, 480, 503, 504, or transport errors.

### External Call Transfers

Transfer inbound PSTN calls to external destinations while preserving the original caller's identity. Requires a SIP `Diversion` header containing the Telnyx number.

### Adaptive Jitter Buffer

Smooths packet arrival variation on SIP connections. Configure `enable_jitter_buffer`, `jitterbuffer_msec_min` (40–400ms), and `jitterbuffer_msec_max` (40–400ms).

### Dynamic E911

Deliver location information to PSAPs during emergency calls via API-based addresses or GPS coordinates (PIDF-LO).

### STIR/SHAKEN

Attestation levels: A (owned numbers), B (non-owned/verified). Certificate selection based on origin and destination. The `verstat` parameter in `P-Asserted-Identity` indicates validation status.

## WebRTC SDKs

Telnyx provides WebRTC Voice SDKs for JavaScript, iOS (native), Android (native), and Flutter. The SDKs establish a WebSocket connection to `rtc.telnyx.com` for signaling and use WebRTC for media.

### Authentication

- **Credential-based SIP connection** — username/password
- **Telephony credentials** — dynamic credentials with optional expiration
- **JWT** — token-based authentication (24-hour validity)

### Call Flow

WebRTC SDKs cannot orchestrate call flows alone. They require Call Control API or TeXML for advanced call handling. Two common patterns: client-initiated (park outbound calls) and inbound-driven (queue/conference then bridge).

### Push Notifications

Push notifications bridge the gap when the app is in the background. Android uses Firebase Cloud Messaging (FCM); iOS uses Apple Push Notification Service (APNS) with VoIP certificates. Up to 5 push tokens per user across devices.

### Debug Data

Enable debug mode to collect WebRTC statistics, stored in Telnyx Cloud Storage and visualizable at `https://webrtc-debug.telnyx.com/`.

## Voice Design Lab

The Voice Design Lab enables creating custom voices via two methods:

- **Design a Voice** — generate a synthetic voice from a natural language description (age, tone, accent, pacing). Uses Telnyx (Qwen3TTS) or Minimax providers.
- **Clone from Audio** — upload an audio sample to capture a speaker's vocal characteristics. Supports Qwen3TTS (3–15s), Ultra (up to 10s), and Minimax (10s–5 min).

## UAC Connections (SIP Attach)

UAC Connections let Telnyx register to your PBX as a SIP endpoint, connecting existing SIP infrastructure to Telnyx services without a PSTN hop. Configure `external_uac_settings` (proxy, credentials, transport) and `internal_uac_settings` (destination URI routing).

## L1 Account Restrictions

L1 verified accounts have restrictions: machine-generated speak commands are prepended with an abuse-reporting message, limited to 100 outbound calls per day and 10 per hour.

## Voice API Services in Europe

Use `https://api.telnyx.eu` for reduced latency on calls held in Europe. Set AnchorSite to Frankfurt, London, or Amsterdam. Conference and queue participants must be in the same region.

## SIP Response Codes

Telnyx-specific D-series codes indicate account/connection issues (D1–D9), profile/channel limits (D2x), connection/URI issues (D3x), routing/destination issues (D4x), channel billing/verification (D5x), account tier restrictions (D6x), and additional restrictions (D7x–D9x). P-series codes indicate protocol violations. R-series codes indicate registration/authentication issues.
